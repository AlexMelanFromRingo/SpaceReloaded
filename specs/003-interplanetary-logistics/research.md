# Research: Межпланетная логистика

## R1. Откуда брать Δv перелётов

- **Decision**: таблица в профиле тела (`transfer_delta_v`), значения выведены из уравнения Гомана между круговыми орбитами и инъекции из парковочной орбиты (патч-коники), тест ядра сверяет JSON с формулой.
- **Rationale**: реальные параметры орбит дают числа (Луна 3955, Марс 3613, возвраты 822/2103), сопоставимые с Δv ракет мода (1 бак+двигатель ≈ 2886 м/с, 3 бака ≈ 4314 м/с) — прогрессия «3 бака = Луна, ступени/ISRU = Марс/пояс» получается сама. Хранение в данных даёт аддонам свободу, формула в тесте не даёт числам «оторваться» от физики.
- **Alternatives considered**: вычислять из радиусов орбит прямо в ядре (нужно расширять профиль μ/радиусами и родительским телом — тяжело для аддонов); масштабировать под игровые высоты (√(L_game/L_real) ≈ 0.04 — цены ~150 м/с, перелёт стал бы дешевле подъёма, экономика ISRU не работала бы).

## R2. Аэрозахват и прямой вход

- **Decision**: прибытие к телу с атмосферой (Земля, Марс) — прямой вход/аэрозахват без второго импульса; к телу без атмосферы (Луна, астероид) — второй импульс входит в таблицу.
- **Rationale**: соответствует реальным миссиям (Apollo/Orion — прямой вход; Mars 2020 — прямой вход); в игре спуск после прибытия моделируется честно (suicide-burn-lite / вход с нагревом).
- **Alternatives**: считать захват всегда (симметрично, но Марс-возврат 4 км/с ломает одноступенчатый метанокс — цель US4).

## R3. Списание через ступени при переходе

- **Decision**: `TransferBurn` последовательно сжигает ступени; сгоревшие отбрасываются без спавна обломка.
- **Rationale**: обломок ступени на орбите перелёта не принадлежит ни одному измерению; спавнить его в измерении старта на высоте перехода физически неверно и засоряет мир.
- **Alternatives**: разрешать только активную ступень (пилот вынужден вручную отделять до перехода — неудобно для беспилотников).

## R4. Планировщик посадки

- **Decision**: v_кас = √(v₀² + 2gh), Δv = v·TWR/(TWR−1), запас конфигом; атмосферное торможение игнорируется.
- **Rationale**: аналитический вывод для торможения постоянной тягой; консервативная оценка для тел с атмосферой (реальный расход меньше) — «предохранитель» против недозаправленных линий.
- **Alternatives**: численное моделирование спуска (дорого и требует профиля атмосферы цели на каждом плане; терминал считает редко, но HUD — часто).

## R5. Где хранить линию

- **Decision**: блок-сущность терминала на каждой площадке; линия = два терминала со встречными программами.
- **Rationale**: децентрализованно, переживает выгрузку (NBT), не требует реестра/GUI; реиспользует предмет-программу и маяки; удалить/переключить одну сторону не ломает другую.
- **Alternatives**: глобальный реестр линий в SavedData с GUI (больше кода, дублирует программу; отложено в бэклог как «диспетчерская»).

## R6. Стыковочный порт как люк

- **Decision**: `DockingPortBlock extends HermeticHatchBlock` + FACING; ПКМ — люк, Sneak+ПКМ — конверсия.
- **Rationale**: после конверсии стенка модуля становится люком, а порт остаётся герметичной дверью станции — получается двухдверный переход из геометрии (интерлок люков работает), без новой механики шлюза.
- **Alternatives**: порт — сплошной блок, который игрок потом меняет на люк (лишние действия); порт исчезает после стыковки (теряется дверь станции).

## R7. Обшивка модуля — отдельный блок

- **Decision**: `module_hull` без рецепта, герметичный, добываемый.
- **Rationale**: видимая «биография» станции (модуль был ракетой), нельзя получить дешевле, чем вывести массу ракетой; переставляем — игрок дорабатывает модуль.
- **Alternatives**: превращать в `hull_plating` (теряется смысл wet workshop, обшивка дешевле бака).

## R8. Стенд и другие измерения

- **Decision**: сценарий линии проверяет отказ, заправку, автозапуск и счётчики на стороне старта; прибытие/пересадку — тесты ядра и модульная логика; лёд — скан чанков Марса без игрока.
- **Rationale**: харнесс не переносит игрока и не отслеживает свежие сущности в чужом измерении (см. api-notes 26.2).

## R9. Марсианская порода

- **Decision**: жилы льда в `minecraft:red_sandstone` (default_block Марса) с `discard_chance_on_air_exposure: 0`.
- **Rationale**: тот же контракт, что у `mars_tungsten`; красный песчаник — базовый камень Марса в noise_settings.

## R10. Синхронизация HUD

- **Decision**: цена следующего хопа — synched float `DATA_TRANSFER_DV` (без нового пакета).
- **Rationale**: HUD уже читает synched data ракеты; расчёт дешёвый (таблица + Циолковский), симуляция подъёма на клиент не нужна.
