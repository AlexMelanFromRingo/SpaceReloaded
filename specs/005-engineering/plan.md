# Implementation Plan: Инженерия — трансмиссия, станки, молот, мультиблоки, детали двигателей

**Branch**: `005-engineering` | **Date**: 2026-09-24 | **Spec**: [spec.md](spec.md)

## Summary

Механика вращения в СИ (τ, ω, P = τ·ω) с событийной топологией и решателем «одно ω на сеть»; валы с пределом кручения, муфта-предохранитель, мотор-генератор (мост к энергии по 15 кДж/E), маховик с разрывом; пресс и токарный станок от вала с рецептами и допусками; детали двигателя (турбонасос, форсуночная головка, регенеративное сопло), качество которых — свойство состояния блока двигателя и честно меняет Isp/тягу; инженерный молот и датапак-шаблоны мультиблоков; электролизный стек (Фарадей) и ректификационная колонна (Фенске) поверх существующих станков; руководство инженера; ветроколесо (стретч). Физика — чистое ядро `core.kinetics`, `core.industry`, `core.multiblock`; мод — блоки, BE, BER, рецепты, экраны, стенд.

## Ключевые проектные решения

### D50. Граф и отношения (FR-301/FR-302)
Мод строит граф BFS от изменённого/запрошенного узла по правилам связности (осевые: вал, муфта-замкнута, мотор, маховик, станки, ступица, шестерни по своей оси, f = +1; малые шестерни по граням в плоскости, f = −1, η_зац; большая ↔ малая по диагонали в плоскости, f = −2 (ω_малой = −2·ω_большой), η_зац; угловой редуктор: узел хранит «окружную» скорость s, сосед по грани d получает ω = s·sgn(d), η_кон). Ядро `KineticGraph.analyze()` задаёт r₀ = 1, e₀ = 1, rᵦ = f·rₐ, eᵦ = eₐ·η; любое непокрывающее ребро с |rᵦ − f·rₐ| > 1e-6·max(|r|) → JAMMED. Предел `kineticMaxBlocks` → TOO_LARGE.

### D51. Решатель (FR-303/FR-304)
Каждый узел даёт линеаризацию источника (a, b) в своей системе: τ ≈ a − b·ω_loc (мотор: a = k·τ_st, b = k·τ_st/ω₀, k — доступность энергии; ветер — касательная к τ(ω)), константную нагрузку c ≥ 0 (трение блока, станок/удар пресса — противодействует вращению), инерцию I. Приведение к опорному: A = Σ r·e·a, B = Σ r²·e·b, C = Σ |r|·c/e, J = Σ I·r². Неявный шаг: ω' = (J·ω + dt·(A − C·sgn))/(J + dt·B), sgn = sign(ω) (при ω = 0 — sign(A)); если при ω = 0 |A| ≤ C — покой; смена знака ω при торможении → 0. Равновесие: |Δω| < 1e-4·max(1, |ω|) 20 тиков подряд → сон. Моменты через узлы: net_i = r·e·(a − b·ω_loc) − |r|·c·sgn/e − I·r²·α (α = (ω' − ω)/dt), в покое нагрузки берутся с коэффициентом A/C (реакции уравновешивают); поддеревья суммируются обратным BFS; момент через узел = |S_i|/|r_i|. Генерация мотора: τ_loc·ω_loc < 0 → P_ген = |τ·ω|·η.

### D52. Прочность, муфта, маховик (FR-305/FR-306/FR-310)
Валы: τ_max = π·d³·τ_y/16 (d 0.25 м; сталь τ_y 230 МПа → 706 кН·м; дерево 8 МПа → 24.5 кН·м). Проверка после шага для узлов-валов/муфт; превышение — `destroyBlock(pos, true)` в конце тика сети, топология пересобирается. Муфта: τ_slip из конфига (50 кН·м) — срабатывает (свойство TRIPPED), разрыв связи до переднего фронта редстоуна. Маховик: I 385 кг·м², ω_max 703 рад/с; при |ω_loc| > ω_max — взрыв `level.explode` силой по E (TNT-эквивалент 4.184 МДж, мощность ∝ ∛(E/E_tnt), потолок радиуса из конфига), флаг разрушения блоков.

### D53. Синхронизация и рендер (FR-308)
KineticBlockEntity: ω_loc, угол₀, t₀ → update tag; сеть рассылает при |Δω|/max(|ω|,1) > 3 % (не чаще 5 тиков) и при переходе в покой; угол₀ пересчитывается непрерывно: угол₀' = угол₀ + ω_old·(t − t₀). BER: угол = угол₀ + min(|ω|, ω_vis)·sgn·(t − t₀), ω_vis = 40 рад/с (≈ 380 об/мин — выше стробоскоп). Вращающиеся блоки — `RenderShape.INVISIBLE`, BER рисует модель вспомогательного блока-ротора (без предмета) — `BlockModelResolver` как у салазок 004; у мотора/маховика/станков корпус — модель самого блока, BER — только ротор/шток.

### D54. Станки (FR-311/FR-312)
База `KineticMachineBlockEntity` (контейнер: вход, выход; окно ω_loc). Пресс: период удара `pressCycleTicks` 40; удар 4 тика — нагрузка c = W/(t_удара·ω_ном) приводится к сети; завершение цикла — рецепт `spacereloaded:pressing`. Токарный: при работе нагрузка c = P_ном/ω_ном; прогресс += |τ·ω_loc|·dt; завершение при E_оп рецепта (`spacereloaded:machining`, поле `energy_j`). Оба пишут в полуфабрикат шаг и Σδ² по среднему |ω/ω_ном − 1| за операцию (D56).

### D55. Шаблоны и молот (FR-320…FR-324)
Реестр `spacereloaded:multiblock` (синхронизируемый): `{ "key": id, "cells": [{"offset":[x,y,z], "block": id|"#tag"}], "repeat": {"cells":[…], "step":[x,y,z], "min", "max", "display"} }`, локальная система: +z — задняя сторона ключа (против FACING), +y — вверх; повороты по FACING ключа (если есть). Ядро: `MultiblockTemplate.match(CellProbe)` → Result(formed, repeats, badCell, expected). Молот (ПКМ по ключу): для шаблонов стека/колонны — формирование (контроллер хранит `formedCount`, претендует на клетки + следующую за сегментом); для катапульты и реактора — их отчёт. Событие изменения клетки → переоценка: валидно — обновить счёт, иначе — расформировать.

### D56. Допуски и качество (FR-330…FR-334)
`MachiningTolerance`: δ = δ_ст·(1 + k_ω·dev); Σδ² += δ²; q = clamp(1 − √Σδ²/δ_брак); балансировка: Σδ² ← Σδ²/4. Цепочки (рецепты с полем `step`): турбонасос — токарный(сплав→1) → токарный(2) → пресс(3) → токарный-балансировка(→ деталь); форсуночная головка — пресс(медь→1) → токарный(2) → токарный(3) → токарный(→ деталь); сопло — пресс(медь→1) → пресс(2) → токарный(→ деталь). Качество детали — компонент `part_quality` (float). Двигатель: блок `EngineBlock` со свойством `quality` 0…10 (по умолчанию 8 — таблица); AssemblyRecipe.assemble: результат-двигатель с деталями → уровень = round(10·mean(q)); без деталей → 5; уровень кладётся в компонент `minecraft:block_state` результата (ванильная установка применит). `PartPropertiesResolver` кэширует по BlockState и умножает Isp/тягу на `EngineQuality.multipliers(level/10)`.

### D57. Стек и колонна (FR-322/FR-323)
Электролизёр: `formedCells` N; за цикл перерабатывает k = min(N+1, лёд) единиц, энергия цикла ×k, топливо и O₂ ×k (энергия/кг — как у наследия, κ). Перегонный куб: `formedTrays` K ≥ 4 → выход на сланец `ColumnYield.yield(K, 100)`; иначе — наследные 100. Анимации: частицы (пузыри BUBBLE над ячейками при работе, CLOUD над верхней тарелкой) — серверные `sendParticles` раз в 10 тиков работы (дёшево, без BER).

### D58. Руководство (FR-325)
`EngineerManualScreen`: слева — оглавление (механика, станки, детали, мультиблоки из реестра шаблонов), справа — текст страницы (`textWithWordWrap`) и для мультиблока — слайдер слоя и сетка иконок `gfx.item(stack, x, y)` (research-api §3), список материалов с количествами (repeat — по `display`).

### D59. Ветроколесо (FR-340)
Ступица (ось горизонтальна) + паруса — связная группа парусов в плоскости, перпендикулярной оси, касающаяся ступицы; R = max расстояние паруса; ρ — плотность атмосферы профиля тела; v — `windSpeed` тела (конфиг: Земля 8, Марс 8, буря Марса 25); τ(ω) = P(ω)/ω с C_p(λ) (при ω → 0 — стартовый момент по λ_min = 1). Ветер пересчитывается раз в 200 тиков (будит сеть).

### D60. Взрывы и герметичность (T024)
Research-api §5: взрыв уже проходит через `sendBlockUpdated` → `ServerLevelMixin` → ZoneManager. Стенд проверяет (герметичная комната → взрыв → утечка), TODO в `SpaceReloaded.java` закрывается комментарием с объяснением.
